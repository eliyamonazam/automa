# تصمیم‌های فنی

هر تصمیم: تاریخ، تصمیم، دلیل، گزینه‌های ردشده.

## D1 — درگاه مدل سازگار با OpenAI (۱۴۰۵/۰۸/۱۸ · 2026-11-09)
**تصمیم:** همه فراخوانی‌ها از یک کلاینت با API سازگار OpenAI Chat Completions انجام می‌شن؛ `base_url` و کلید قابل تنظیم‌ان.
**دلیل:** بیشتر درگاه‌های چندمدلی (OpenRouter و مشابه‌ها) همین استاندارد رو پیاده کردن. با تغییر تنظیمات می‌شه درگاه یا ارائه‌دهنده رو عوض کرد. خواسته کاربر استقلال از ارائه‌دهنده‌ست.
**ردشده:** استفاده مستقیم از SDK یک شرکت (وابستگی)؛ فریم‌ورک‌های سنگین چندعاملی (کنترل کمتر روی بودجه و راستی‌آزمایی).

## D2 — محدودیت مالی در کد، نه در Agent (2026-11-09)
**تصمیم:** سقف‌های بودجه توسط `BudgetGuard` قبل از هر فراخوانی اعمال می‌شن. Agent مالی فقط تحلیل و پیشنهاد می‌ده.
**دلیل:** کاربر کنترل مالی «سفت و سخت» خواسته. هر قانونی که فقط در prompt باشه می‌تونه نادیده گرفته بشه. علاوه بر این، کاربر در داشبورد درگاه هم سقف خرج می‌ذاره (لایه دوم حفاظت).

## D3 — ذخیره‌سازی فایل‌محور + SQLite (2026-11-09)
**تصمیم:** وضعیت پروژه در فایل‌های JSON، و Ledger هزینه در SQLite.
**دلیل:** بدون سرور جدا، قابل بررسی دستی، قابل ادامه بعد از توقف. در صورت نیاز بعداً به PostgreSQL منتقل می‌شه.

## D4 — ارزیابی مستقل با اولویت بررسی‌های قطعی (2026-11-09)
**تصمیم:** Verifier خروجی و معیار پذیرش رو می‌بینه، نه گفت‌وگوی Worker. اول بررسی‌های قطعی (تست، اجرای دستور، وجود فایل) و بعد ارزیابی مدلی.
**دلیل:** مدل‌ها نقطه‌کور مشترک و تمایل به موافقت دارن؛ اجماع بین Agentها جای راستی‌آزمایی بیرونی رو نمی‌گیره.

## D5 — چیدمان `src/` با hatchling و ruff (2026-11-08)
**تصمیم:** کد در `src/automa/` با build backend `hatchling`؛ نصب توسعه با `pip install -e '.[dev]'`. قواعد ruff: `E,F,W,I,B,UP,S` (شامل قواعد امنیتی bandit)، طول خط ۱۰۰. نسخه پکیج در `__init__.py` و `pyproject.toml` تکرار شده و یک تست هم‌خوانی‌شون رو چک می‌کنه.
**دلیل:** چیدمان `src/` جلوی import تصادفی از پوشه جاری رو می‌گیره؛ hatchling سبک و استاندارده؛ قواعد `S` از همون اول کدهای ناامن (مثل `shell=True`) رو علامت می‌زنه.
**ردشده:** Poetry (ابزار اضافه برای اجراهای خودکار)، setuptools (پیکربندی پرحرف‌تر)، نسخه پویا از git (وابستگی به تگ‌ها).
